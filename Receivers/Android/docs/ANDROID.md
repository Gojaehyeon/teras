# Teras Android receiver

The Android half of Teras. It **listens** on TCP 41777 and the Mac dials in,
over `adb forward` for USB or over the LAN address advertised as `_teras._tcp`.
The wire contract is `docs/PROTOCOL.md` at the repository root, and the
authoritative interop vectors are `docs/VECTORS.md` there, generated by the
Swift reference implementation. The readings this receiver takes where the
protocol document is ambiguous are in [INTEROP-NOTES.md](INTEROP-NOTES.md).

* Kotlin, Jetpack Compose (Material 3)
* `minSdk 26`, `targetSdk 35`, `compileSdk 35`
* package and application id `app.teras.receiver`

## Prerequisites

* JDK 17 or newer. Android Studio ships one:

  ```sh
  export JAVA_HOME="/Applications/Android Studio.app/Contents/jbr/Contents/Home"
  ```

* The Android SDK with platform 35 and build-tools 35. `local.properties`
  points at `~/Library/Android/sdk`; change `sdk.dir` if yours is elsewhere.

Gradle 8.11.1, AGP 8.7.3 and Kotlin 2.0.21 are pinned through the wrapper and
`gradle/libs.versions.toml`. No global Gradle install is needed.

## Build

```sh
cd Receivers/Android
./gradlew assembleDebug            # debug APK
./gradlew testDebugUnitTest        # JVM tests, no device needed
./gradlew assembleRelease          # minified, debug-signed for now
./gradlew installDebug             # build and install on the attached device
```

The debug APK lands at:

```
app/build/outputs/apk/debug/app-debug.apk
```

## Run

1. Enable Developer options and USB debugging on the device.
2. `adb install -r app/build/outputs/apk/debug/app-debug.apk`
3. Launch Teras on the device. The idle screen shows the device name, the
   listening state and the Wi-Fi address.
4. Start the Mac host, which finds the device over adb and dials in.

## Test the socket without the Mac host

The receiver is listening as soon as its screen is up. Forward its port to the
development machine:

```sh
adb forward tcp:0 tcp:41777        # prints the allocated local port, e.g. 53422
```

Then dial `127.0.0.1:<port>` and speak the protocol. A minimal USB handshake in
Python, which drives the receiver all the way to the streaming state:

```python
import json, socket, struct, base64, os

PORT = 53422                                    # from adb forward
s = socket.create_connection(("127.0.0.1", PORT))
s.setsockopt(socket.IPPROTO_TCP, socket.TCP_NODELAY, 1)

def send(t, payload=b""):
    s.sendall(struct.pack(">IB", len(payload) + 1, t) + payload)

def recv():
    head = s.recv(4, socket.MSG_WAITALL)
    (n,) = struct.unpack(">I", head)
    body = s.recv(n, socket.MSG_WAITALL)
    return body[0], body[1:]

send(0x01, json.dumps({
    "pv": 1,
    "hostId": "11111111-1111-1111-1111-111111111111",
    "hostName": "dev box",
    "transport": "usb",
    "hostNonce": base64.b64encode(os.urandom(16)).decode(),
    "encrypt": False,
    "app": {"name": "Teras", "version": "0.0.1", "build": 1},
}).encode())

t, payload = recv()                              # 0x02 HELLO_ACK
print(hex(t), json.loads(payload))

send(0x10, json.dumps({
    "codec": "h264", "wPx": 1920, "hPx": 1080, "fps": 60,
    "desktop": {"w": 960, "h": 540}, "orientation": "landscapeLeft",
    "mode": "extend", "cursorBaked": True,
}).encode())

print(hex(recv()[0]))                            # 0x11 READY
```

From there the receiver answers PING with PONG, sends its own PING every second,
emits STATS once per second while a decoder is up, and forwards touches as
0x20 TOUCH frames. Feed it Annex-B access units as 0x12 VIDEO frames to see a
picture.

Remove the forward when you are done:

```sh
adb forward --remove-all
```

## Testing over Wi-Fi

Put the Mac and the device on the same network. The receiver registers
`_teras._tcp` on port 41777 with TXT keys `pv`, `id`, `plat` and `name`. Check
it from the Mac:

```sh
dns-sd -B _teras._tcp
dns-sd -L "<device name>" _teras._tcp
```

A LAN host must pair: the receiver shows a six-digit PIN, the Mac asks for it,
and three wrong attempts rotate the PIN and drop the connection. Clear stored
pairings from the receiver's settings screen.

```
  input/                   viewport normalisation
  video/                   parameter-set extraction, stats window
```

## Behaviour worth knowing

* **One session at a time.** A new inbound connection replaces the old one; the
  previous session gets a BYE and its decoder is torn down.
* **Liveness.** PING every second in both directions; three seconds without a
  PONG drops the connection.
* **Rotation.** The activity handles configuration changes itself, so the socket
  and decoder survive; the host is told with DEVICE_CONFIG instead.
* **Screen.** The window keeps the screen on (a setting) rather than holding a
  wake lock, and no foreground service is needed because the receiver is only
  useful in the foreground.
* **Stats.** Triple-tap the picture while streaming to toggle the overlay.
* **Pairing secrets** live in `EncryptedSharedPreferences`, keyed by an
  AES-256-GCM master key in the platform keystore. If the keystore is unusable —
  it has been reset, or the stored file no longer matches its key — the store
  falls back to a uid-private `MODE_PRIVATE` file with Base64 values rather than
  refusing to start, and says so through `isEncrypted`. Clear every secret from
  the settings screen.
